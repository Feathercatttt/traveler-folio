# 更新与镜像下载

> 本项目由 AI 辅助生成与维护。更新前建议导出角色 JSON 备份；实体手机与真实枭熊多人房间仍需使用者核对。

## 第一次启用

v0.19 及以前没有更新器，需要先手动安装 **v0.20.0** 一次。Windows 退出旧 EXE 和桥接后，完整解压新版并打开 EXE；APK 使用原签名，直接覆盖安装，**不要卸载旧版**。以后使用应用内更新。

| 平台 | 更新入口 | 安装行为 |
| --- | --- | --- |
| Windows EXE | 顶部“更新”，或托盘“检查更新 / 下载设置” | 下载小型更新包，保存记录、关闭应用、备份替换文件并重新打开；失败时尝试恢复旧文件 |
| Android APK | 底部“更多”→“检查更新 / 下载设置” | 下载并核验同一包名、版本号和原 APK 签名，打开系统安装窗口，由你确认更新 |
| 普通 HTML | GitHub Releases 手动下载 | 不显示原生更新按钮 |
| 枭熊联动 | 更新 EXE 后刷新枭熊页面 | 保留原 localhost 安装地址，跟随 EXE 内的桥接和插件文件更新 |

默认在启动 4.5 秒后后台检查，每 6 小时最多自动检查一次。发现新版只提示，不中断跑团；点击“下载安装包”，完成后再选择“保存并更新重启”或“打开系统安装确认”。可关闭自动检查，手动检查不受 6 小时限制。已下载的安装包可在重开应用后继续安装，也可以继续检查更高版本。

关闭更新页面不会取消正在进行的下载；需要取消时点击页面中的“取消”按钮。取消或下载中断后重新下载，当前版本仍可继续使用。

## 国内下载线路

默认优先使用三条公共 HTTPS 镜像，失败后自动尝试其他线路和 GitHub 直连：

- `https://gh-proxy.org/`
- `https://ghfast.top/`
- `https://ghproxy.net/`

检查版本时并行访问备用线路，选取签名有效且版本号最高的信息，避免单条镜像缓存旧版本。下载时依次切换线路，每次都核对文件大小和 SHA-256，错误网页、截断文件和损坏文件不会安装。

在“检查与下载设置”中可选优先线路，或填写兼容 **镜像前缀 + GitHub 完整原地址** 格式的自定义 HTTPS 镜像。自定义镜像优先于其他线路；留空使用内置线路。不需要 GitHub 登录，不向镜像发送账号令牌，不上传角色或卡库资料。

2026-10-16 在开发电脑网络测试了上述镜像的公开版本文件和 APK。此结果不代表覆盖全国所有运营商；公共镜像会调整、限速或停止服务，**不能承诺永久或所有国内网络可达**。如需长期受控的国内下载保障，应使用自己维护的 HTTPS 镜像，将地址填入设置。

## 安卓安装提示

第一次可能要求在系统设置中“允许来自此来源的应用”，仅为允许旅人手札安装自己的更新。返回应用后会继续打开系统确认窗口；取消可稍后再次安装。系统最终安装确认不会绕过，也不需要 root、Google Play 或卸载旧版。

若系统提示签名不同，请确认安装的是本仓库正式 APK。自行编译的新签名 APK 无法覆盖正式版。不要为解决签名冲突而直接卸载有数据的旧版，应先导出备份。

## Windows 文件与数据

程序文件夹需要可写；推荐解压到用户自己的文件夹。更新包不附带庞大的 WebView2 离线安装器，保留已经安装的环境。首次缺少环境仍可以使用完整包。

角色与卡库仍在原 WebView2 数据目录 `%LocalAppData%\TravelerFolio\webview`，桥接缓存仍在 `%LocalAppData%\TravelerFolio\bridge`，更新不修改这些目录。更新状态、缓存与替换备份在 `%LocalAppData%\TravelerFolio\updates`。

如果替换失败，更新器尝试回滚并重新启动旧程序，详细结果和备份留在 updates 目录。关闭旧桥接、其他同目录程序或文件占用后再试。不要在更新器工作时移动或删除程序文件夹。

## 维护发布

应用内置 RSA 公钥；`updates/stable.json` 是 RSA-SHA256 签名信封，其 payload 是 UTF-8 JSON 的 Base64。即使经公共镜像下载，也必须通过发布签名，再验证对应安装包的大小与 SHA-256；APK还要与已安装应用签名一致。

Windows 更新包根目录固定为 `TravelerFolio-Update/`。更新器拒绝路径穿越、绝对路径、ADS、重复文件、符号链接和异常解压大小。已见过的高版本信息不会被较旧镜像覆盖，不支持应用内降级。

维护流程：构建并验证最终 APK/Windows 包 → 计算哈希 → 创建 Release 并上传文件 → 核对远端 SHA-256 并公开 → 用 `work/update-release20.py sign payload.json updates/stable.json` 签名 → 提交更新清单到 main → 检查镜像读取。安装包必须先公开，再提交清单。示例 payload 与签名工具源码随仓库提供。

**更新私钥和 Android 签名私钥只保存在维护者本地，不在 GitHub 或安装包中。** 应另行安全备份；不要运行 init 覆盖已有公钥来发布旧客户端的更新。Fork 项目需要生成自己的密钥、公钥与发布地址，并重新构建；原客户端不会信任别人的发布签名。

实现参考：[GH-Proxy 官方说明](https://gh-proxy.com/docs/github-accelerator)、[Android 安装权限接口](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls())、[Android 临时文件读取授权](https://developer.android.com/training/secure-file-sharing/share-file)。
